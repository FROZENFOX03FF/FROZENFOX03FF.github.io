Première partie : Analyse de la base KDou

Dans cette partie, nous allons présenter la base de données, les problèmes trouvés et les améliorations possibles.

Numéro 1

A) Présentation de la base de données

En regardant la base de données KDou, nous avons remarqué qu'elle est organisée en plusieurs tables. On y trouve notamment les clients, les commandes, les produits, les fournisseurs, les pays et les catégories.

La base utilise plusieurs éléments pour bien fonctionner :

  • Chaque table possède une clé primaire qui permet de retrouver chaque élément sans le confondre avec un autre (CodeCli, RefProd, NoCommande, etc.).
  • Les clés étrangères permettent de faire des liens entre les différentes tables, par exemple entre les produits et les fournisseurs.
  • Les données sont réparties dans plusieurs tables pour éviter de répéter trop souvent les mêmes informations.

Cette organisation permet de retrouver plus facilement les informations et de suivre les commandes et les produits.

Présentation de quelques tables :

SCHEMA RELATIONNEL GLOBAL

Clientele (CodeCli, Societe, Contact, NoPays, Ville, ...)

Produit (RefProd, NomProd, CoutAchat, #NoFour, #CodeCateg)

Commande (NoCommande, DateCde, #CodeCli, Port, AlivAv)

DetailCommande (#NoCommande, #RefProd, Quantité, Remise)

Numéro 2

B) Les problèmes trouvés dans les données

En regardant les informations de la base, nous avons trouvé quelques erreurs et des données qui ne sont pas toujours bien écrites.

Voici les principaux problèmes :

  • Certains noms de villes ne sont pas écrits de la même façon. Par exemple : Besancon et Besançon.
  • Certains pays ont plusieurs écritures différentes, comme USA, U.S.A et États-Unis.
  • Nous avons aussi remarqué des erreurs dans certains identifiants, par exemple Folk0 à la place de Folko.
  • Certaines remises semblent mal renseignées, comme 0,15 % à la place de 15 %.
  • Il manque parfois des informations sur certains clients ou produits.

Ces erreurs peuvent rendre les recherches moins fiables et compliquer le travail de l'entreprise.

Résumé des problèmes :

PROBLEMES TROUVES

Livraison : certaines erreurs peuvent provoquer des problèmes de livraison

Ventes : les doublons peuvent fausser les résultats des ventes

Clients : certaines erreurs peuvent rendre le suivi des clients plus difficile

Numéro 3

C) Les premières recherches effectuées

Nous avons réalisé quelques recherches dans la base de données pour mieux comprendre comment fonctionne KDou.

Nous avons notamment cherché :

  • Le nombre de fournisseurs qui se trouvent dans l'Union européenne.
  • Les clients qui n'ont jamais passé de commande.
  • Le nombre de clients qui habitent à Paris.

Ces recherches nous permettent de mieux connaître les clients et les fournisseurs de KDou. Elles peuvent aussi aider l'entreprise à mieux organiser ses livraisons.

Quelques résultats obtenus :

RESULTATS DES RECHERCHES

Fournisseurs dans l'Union européenne : 19

Clients qui n'ont jamais commandé : 2

Clients situés à Paris : 5

Numéro 4

D) Nos idées pour améliorer la base de données

Après avoir étudié la base de données, nous avons trouvé plusieurs choses qui pourraient être améliorées.

Voici nos principales idées :

  • Utiliser des choix déjà préparés pour éviter les différences d'écriture dans les villes, les pays et les numéros de téléphone.
  • Corriger les erreurs dans les identifiants et supprimer les doublons.
  • Compléter les informations qui sont manquantes.
  • Faire attention aux cases vides et aux valeurs comme NULL ou 0, car elles ne veulent pas dire la même chose.

Ces changements permettraient d'avoir une base de données plus propre et plus facile à utiliser.

Les actions à faire :

NOS PROPOSITIONS

1. Mettre des règles pour éviter certaines erreurs de saisie

2. Corriger les anciennes erreurs et supprimer les doublons

3. Expliquer aux utilisateurs comment bien remplir les informations
